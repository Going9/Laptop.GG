# LaptopGG UI 기준

기존 Kotlin/Spring Boot/Thymeleaf와 일반 CSS/JavaScript를 유지한다. 추천 입력, 결과, 상세, 공통 헤더, 오류와 빈 상태가 하나의 UI를 공유한다.

- 흰 표면과 밝은 중립 배경, 짙은 본문, 대비가 확보된 보조 텍스트, 옅은 테두리, 절제된 청색 강조를 CSS 변수로 정의한다.
- 간격은 4/8/12/16/24/32/48px, 본문 16px, 보조 14px, 제목 24~36px. 한글은 정상 자간과 1.6 줄높이, 기본 굵기 400/500/600을 사용한다.
- 컨트롤 최소 44px, 모서리 6~12px. 그림자는 기본적으로 사용하지 않는다. 그라데이션, 블러, 장식 애니메이션을 제거한다.
- 입력 화면은 작은 소개 뒤에 예산 직접 입력과 빠른 선택을 노출한다. 라디오/체크박스는 키보드 접근 가능한 실제 input을 유지한다.
- 결과는 동일한 이미지 비율과 사양 열을 공유한다. 제품명 → 가격 → 추천 이유 → 핵심 사양 순서로 읽는다. 제목이나 이유를 줄 수 제한으로 자르지 않는다.
- 상세는 이미지·제품명·가격·주요 행동을 먼저 보여준다. 사양은 분류하고 댓글 입력과 수정/삭제는 문서 흐름 안에서 펼친다.
- 모바일 우선, 360~1440px. 큰 화면에서는 결과 카드와 상세를 가로 배치한다. 페이지 overflow를 숨기지 않고 min-width:0, 줄바꿈, 유동 열로 해결한다.
- 포커스 링, 선택 표시, 비활성 표시, 입력 레이블, 필수/범위 검증을 유지한다. 이미지가 비거나 로딩에 실패하면 공통 로컬 대체 이미지를 사용한다.

조건 수정은 기존 요청의 예산·무게·화면·용도를 GET 바인딩으로 다시 채운다. 정렬과 페이지 이동은 기존 POST hidden 필드를 유지한다. 추천 알고리즘과 DB 스키마는 변경하지 않는다.

HTTP 바인딩 조사에서 드러난 두 문제도 화면 동작 보존 범위에서 수정한다. `th:field`는 최상위 요청 모델에 바인딩하여 중첩 접두사를 없앤다. 정렬은 Spring의 단일 문자열→List 쉼표 분리를 피하도록 `@RequestParam MultiValueMap`에서 원본 sort 값을 읽는다. URL과 POST 파라미터 계약은 그대로 유지한다.

댓글의 실제 저장 한도는 기존 JPA/Flyway 스키마의 255자다. 입력창의 기존 500자 허용값을 255자로 맞추고 레이블에 표시한다. 공통 생성·수정 validator도 같은 한도를 검사하여 긴 요청이 DB 예외 대신 400 안내로 돌아오게 한다. 스키마와 저장 가능한 기존 데이터 범위는 유지한다.
