# 운영 강화 계획과 완료 기준

기준: 2026-10-15, 단일 웹 VM(메모리 약 1GB), PostgreSQL VM, Cloudflare/Nginx,
하루 약 2천 상품 수집. 다중 서버나 대규모 트래픽을 가정한 구조 변경은 하지 않는다.

## 확인한 문제와 실행 순서

1. **오래된 가격으로 판매 중지 상품 추천**
   가격 파서를 고친 후에도 기본 1위의 상품코드 94025177은 다나와에서 리퍼비시·가격비교 중지였다.
   수집에서 사라진 상품에는 기존 가격이 계속 남는다. 가격 확인 시각을 UTC로 별도 기록하고
   최근 48시간 안에 확인한 가격만 추천하고, 상세/API에서도 오래된 가격을 숨긴다.
   가격이 그대로여도 확인 시각을 갱신하고,
   가격을 못 읽었을 때는 갱신하지 않는다. 기존 자료는 실제 가격 이력 시각으로 이관한다.
   완료 기준: 오래된 상품 제외, 정상 상품 재확인 후 복귀, 미수집으로 유효기간 연장 금지,
   추천 페이지 수와 정렬 일치의 DB 검사 통과.

2. **댓글 입력·반복 요청 방어**
   작성자 길이는 서버에서 제한하지 않았고, 화면의 비밀번호 80자 한도는 bcrypt의 72바이트와 다르다.
   DB/암호화 전에 공통 생성·수정·삭제 검증을 적용한다. 댓글 쓰기에는 IP별 요청 제한을 둔다.
   Cloudflare 주소만 신뢰해 실제 방문자 IP를 복원하며, 외부 전달 헤더로 제한을 우회하지 못하게 한다.
   완료 기준: 경계값 저장 및 초과 요청 400, 잘못된 암호 거절 유지, 반복 쓰기 429,
   일반 조회와 정상 댓글 흐름 유지.

3. **백업과 복구**
   DB 서버에서 앱 전용 백업 timer/cron과 보관 자료를 찾지 못했다. 매일 원자적 백업,
   보관 기간, 실패 기록을 설정하고, 별도 DB에 복원한 뒤 행 수와 스키마를 확인한다.
   완료 기준: 자동 timer 활성, 백업 파일 0600, 실제 복원 검사 통과와 웹 VM 복제본 일치.
   전용 SFTP 키/계정은 백업 폴더 업로드만 허용하고 수신 파일은 원자적으로 게시한다.
   다른 계정·리전의 저장소와 운영자 알림 수신처는 후속 연결 항목으로 남긴다.

4. **배포 실패와 공개 경계**
   `systemctl restart` 자체가 실패하면 `set -e` 때문에 기존 rollback 분기에 도달하지 않는다.
   이 실패도 이전 JAR로 되돌린다. 웹 앱은 loopback에만 바인딩하고 Nginx에서 요청 크기와
   보안 헤더를 적용한다. 현재 main에는 외부 branch protection이 설정되어 있지 않다.
   완료 기준: 재시작 실패/health 실패/성공 경로 검사, localhost health 성공,
   공개 내부 경로 차단과 CDN 응답 헤더 확인. 가능하면 main 필수 CI 검사를 설정한다.

## 검증과 배포

서버·저장·인증 검사를 먼저 실행한다. 화면 디자인을 바꾸지 않으므로 시각 기준을 갱신하지 않는다.
폼 제약 변경은 댓글 동작과 대표 모바일·데스크톱을 확인한다. CI는 대표 36개와 PostgreSQL 검사를
수행하고 동일 run의 JAR를 배포한다. 운영 반영 후 실제 공개 브라우저에서 기본 추천과 원본 가격을
대조하고, 내부 health와 백업/작업 상태를 확인한다.

48시간 가격 유효기간은 실시간 가격 일치를 보장하지 않는다. 수집 실패가 2일 지속되면 오래된
가격을 추천에서 제외하므로 후보 수가 줄 수 있다. 복구는 정상 수집 재실행으로 수행한다.
CPU 점수는 스펙 기반 휴리스틱이다. 실측 벤치마크, 냉각·전력 제한에 따른 기기별 보정,
큰 부하 시험, 외부 저장소 백업 및 알림 연동은 다음 운영 단계의 작업이다.
